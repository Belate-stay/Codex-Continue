# Single-send completion and automatic looping

**Goal:** Stop after one confirmed queue submission or keyboard send by default. Offer an unchecked Loop send option below the chat picker in Auto Continue only. Manual Timer always stops after one successful send.

**Design:** Reuse the existing command lock and content fades. The checkbox aligns with the chat input and follows the accent with a rounded face and eased check feedback. A small circled exclamation button immediately after its label opens the existing rounded explanation dialog with formal localized copy. While running, lock the checkbox with the command; keep help available. Looping retains the command, attachments and exact chosen chat; only a new exhaustion/recovery cycle triggers another send. Unchecked or manual success uses the existing stop/clear behavior and restores idle detection. Stopping invalidates in-flight callbacks.

**Diagnosis:** Native logs show a manual send at 19:07 followed by a user stop at 19:08:18 and no completion log. Queue success is currently downgraded to Unknown when a visible-text heuristic cannot observe delivery, then keyboard fallback/retries run. In addition, synchronous stream reads precede the queue timeout, making that timeout ineffective. Treat a successful queue submission as success, bound process completion and both stream reads, and stop on uncertain delivery without blind resend.
