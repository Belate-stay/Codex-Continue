# Adaptive window implementation plan

**Goal:** Support standard Windows maximize/restore, title-bar double-click and border resizing, with readable layouts at different window proportions and DPI scales. Keep Beta 0.9.1 and all existing continuation, tray, theme and update behavior.

**Architecture:** Keep the existing native WPF controls and vector assets. A focused `MainWindow.Layout.cs` partial handles responsive geometry, caption state, initial bounds and DPI cache refresh. Use native WindowChrome and a PerMonitorV2 manifest. Preserve the original 1120 × 730 layout as the normal starting size, with a 640 × 480 desktop minimum and initial bounds clamped to the current monitor. Maximize fills the current monitor's work area, including monitors at negative virtual-screen coordinates, and retains taskbar access.

**Layout:** Cap the common navigation/content width at 1440 DIP. Below 960 DIP, put the command card above status, stack settings labels above their choices, and allow vertical scrolling. Keep option groups right aligned; allow accent choices and attachments to wrap. Limit desktop content height and reading widths so large windows do not produce stretched controls or excessive spacing between related fields. Scroll bars appear only when needed. Startup/connect art adapts its anchors and display size on short/narrow windows. Update details and log retain readable bounded content, with the notification anchored to the actual window corner. Auto/Manual switching must retain local-only fades.

**Files:** `MainWindow.xaml`, `MainWindow.xaml.cs`, `MainWindow.Layout.cs`, `Loc.cs`, `CodexContinue.csproj`, `app.manifest`; focused responsive/native checks in the existing WPF regression harness. No layout library, whole-window bitmap scaling, new preference or installer behavior.

**Validation limits:** Render-scale coverage verifies native/vector rendering at the target pixel densities; it does not pretend to exercise physical multi-monitor DPI changes. Native maximize/work-area and restore checks use the connected Windows display. Do not change OS display settings or send continuation messages during verification.
