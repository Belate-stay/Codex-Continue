# Release checks, update notification and details

**Goal:** In Beta 0.9.1, check GitHub Releases asynchronously at startup, offer a dismissible bottom-right update card, a title-bar-only Update details page with Back and Download, and a manual Check for updates action beside the About version.

**Preview steering:** This build must always show the startup card for visual review. Show a clearly labeled Beta 0.9.2 preview immediately; replace it with a real newer release if found. Preview details explain that no package exists and keep Download disabled. No fake installer or remote release is created. The repository currently returns an empty published release list.

**Design:** Reuse the existing neutral surfaces, accent brushes, rounded controls and nonlinear easing. Toast entrance/exit uses short opacity and 8 DIP motion; page navigation uses an opacity transition, keeps the title bar, hides the menu, and preserves the underlying mode, draft and armed run. Back restores the underlying screen, including startup/connect screens. Details render release Markdown as native selectable text with basic headings, lists, code and safe web links. Downloads stay inside the app with progress and an Open folder completion action; this scope does not automatically install or replace the executable.

**Release contract:** Read the public release list including prereleases, skip drafts and invalid tags, compare version values, and select a compatible Codex-Continue Windows x64 EXE/MSI/ZIP asset. Use the selected release's download URL, stream to a versioned local Updates folder via a temporary file, check size and SHA256 when provided, then promote the completed file. Startup failures remain quiet; manual failures receive an inline message. Concurrent checks/downloads coalesce. Exiting the process cancels pending work; hiding to tray does not.

**Validation:** Existing `tests/DetectionFrequency.Tests` plus focused HTTP/GUI checks using deterministic in-process responses. Native verification uses the user-requested preview because no real release package is published. Preserve current preferences and the existing continuation lifecycle.
